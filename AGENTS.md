# AI Alibi - Agent Instructions for Gemini Code Assist

## 1. Project Overview

This project is called **"AI Alibi"**. It is an interactive, multiplayer mystery game designed for the EFL (English as a Foreign Language) classroom, specifically targeting young learners (primary to early secondary, A2-B1 levels).

The core of the application is to provide a **pedagogically sound**, engaging, and motivating environment for language practice. It is being developed as part of a university term paper, and its design must be justifiable with academic theories.

### Core Gameplay Loop

- A crime is generated by AI.
- Students, in teams, act as detectives.
- They question a cast of AI-powered witnesses to gather clues.
- The goal is to be the first to correctly identify the culprit and their motive.

## Core Concept
The game requires teams to ask questions to various AI characters to gather clues and identify contradictions. The team must work together to decide which witness to question and what questions to ask to solve the mystery. The AI's function is to role-play as multiple, distinct personalities, providing information based on its assigned character profile.

## Game Modes
Upon starting, the game will offer a choice between "Classic mode" and "Race mode".
* **Classic Mode**: This mode is turn-based and can be used with only a teacher's computer, making it suitable for classrooms where students do not have individual devices. It can also function as a single-player mode.
* **Race Mode**: This is a simultaneous competition mode.

## Customization Settings
The following customization settings will be available:
* **Language level**: A2, B1, B2, C1, C2.
* **Target age**: This is an optional setting that influences the difficulty, tone, and theme of the game.
* **Target vocabulary/topic**: An optional field to focus the game on specific words or subjects.
* **Additional info**: An optional field for further personalization, such as suggesting a theme or including information about the school, classroom, or city.
* **Time limit**.

## Game Setup and Generation
1.  After the teacher or user enters the desired settings, they will click a "generate" button.
2.  The AI will then generate a complete story featuring four witnesses, each with an AI-generated cartoonish or vectoral image, a complete personality, and motives.
3.  Initially, only the crime will be shown; the complete story remains hidden, and teams will not see anything yet.
4.  The teacher or single user has the option to regenerate the entire story or individual witness images until they are satisfied.
5.  Once the "start" button is pressed, the crime is presented to everyone, and the game's timer begins.

## User Interface and Views
When the simultaneous mode is selected, the application will feature different views:

### Moderator View
* This view contains all the controls for the game.
* In competition mode, this view will show the real-time conversations between the teams and the AI characters.

### Presentation View
* This view is designed to be shown on a projector, TV, or presented during online meetings.
* It displays a room link (e.g., `domain/XXXX`) and a QR code that directs users to the room link, along with a list of teams that have joined.
* After the game starts, it shows the crime, the time, and the witnesses. It also indicates which team is currently talking to which witness and displays clues if clue-sharing is enabled.
* When the game is finished, this view shows the leaderboard, reveals the culprit, and explains their motive or the key clue.

### Team View
* This is the interface that teams use, accessed via the room link. Each team uses one device.
* Teams can choose a name, a color, and an emoji to represent themselves.
* During the game, this view shows the crime, time, and witnesses. It also indicates which teams are talking to which witnesses and shows clues if sharing is enabled.
* This view contains a "make an accusation" button for the team to submit their guess.

## Gameplay Mechanics and Rules

### Witness Interaction
* To make the experience more realistic, a witness can only talk to one team at a time.
* When a witness is being questioned by a team, they will appear as unavailable to other teams.
* The game will make it visible which team is currently talking to which witness.
* Each witness will remember its previous conversations.
* A witness's conversation history is not isolated to one team; it will remember what each specific team asked.
* Witnesses may make comments like "you already asked that" or "they keep asking this," but they should not reveal too much about other teams' lines of questioning or thoughts.
* It is not permissible for a team to ask a witness, "What did the other team ask you?".
* Witnesses are programmed to reject any questions that are not related to the crime.

### Race Mode Specifics
* If race mode is selected, there is an option to allow or disallow clue-sharing between teams.
* The mode features a leaderboard organized as follows:
    * **Top**: Teams with correct first guesses, sorted by their finish time.
    * **Middle**: Teams with correct second guesses, also sorted by finish time.
    * **Bottom**: Disqualified teams.

## Disclaimer
There should be a disclaimer stating that the AI can make mistakes and that the game should not be used without adult supervision.

## 2. Pedagogical Framework

The game's design is grounded in several key academic theories. All code and features should align with these principles:

- **Task-Based Language Learning (TBLT):** The game is a "task." The primary goal is to solve the mystery; language is the tool to achieve this outcome. The focus is on **meaningful communication**, not just grammatical accuracy.
- **Sociocognitive CALL:** The application should function as a "discourse community," encouraging social interaction and collaborative problem-solving among students.
- **Digital Storytelling:** The AI-generated narrative provides an authentic and immersive context for language use, making learning more engaging.
- **SAMR Model:** The project aims for the **Redefinition** level by creating a new type of learning task that is only possible through generative AI.

## 3. Technical Stack & Architecture

- **Frontend:** Vue.js 3 (Composition API)
- **UI Framework:** Vuetify
- **Build Tool:** Vite
- **Package Manager:** **pnpm** (always use `pnpm` for commands)
- **Backend:** Firebase
  - **Authentication:** Google Sign-In for the Moderator; Anonymous Authentication for players/teams.
  - **Database:** Firebase Realtime Database for live game state.
- **AI Integration:** **Firebase Genkit** using the **Google Gemini API**. AI calls must be secured and handled through this backend layer, never on the client-side. **App Check** will be used to secure Firebase services.

### Application Views

- **Moderator View:** Teacher-facing controls for creating, customizing, and managing the game.
- **Presentation View:** A read-only view for a shared screen/projector, showing public game state (crime, witnesses, timer, leaderboard).
- **Team View:** The interface for student teams to interact with the game (question witnesses, make accusations).

## 4. Coding Preferences & Style Guide

Please adhere to the following conventions when generating or modifying code:

### **a. Functional Programming Approach**

- **Prefer pure functions:** Where possible, functions should be deterministic and avoid side effects.
- **Immutability:** Avoid directly mutating objects and arrays. Prefer creating new ones (e.g., using the spread syntax `...`).
- **Use Array Methods:** Favour functional array methods (`.map()`, `.filter()`, `.reduce()`, `.forEach()`) over traditional `for` loops for their clarity and predictability.

- **All major functions must be documented with JSDoc.**
- The documentation should clearly explain what the function does, what its parameters are, and what it returns.
